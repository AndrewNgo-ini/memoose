Install

One command per host. It writes a single MCP server entry into the host's own config and copies the skills in. Nothing else is touched.

From source. Memoose is not published on PyPI yet, so install from a checkout of the repository. Everything below assumes you are inside that checkout.

git clone https://github.com/AndrewNgo-ini/mnemoth.git
cd mnemoth
uv sync

Install into a host

uv run memoose install claude               # or: codex | opencode | cursor
uv run memoose install claude --project .   # project scope instead of user scope
uv run memoose status                       # what is installed where

uninstall reverses both. Then restart the host — MCP servers and hooks are read at startup. Run uv run memoose status again if you want to confirm what landed.

What each host gets

HostMCP config writtenSkills copied to
Claude Code~/.claude.json (user) or .mcp.json (project).claude/skills/memoose*
Codex~/.codex/config.toml.agents/skills/memoose*
OpenCode~/.config/opencode/opencode.jsonc or opencode.jsonc.config/opencode/skills/memoose* (user) or .opencode/skills/memoose*
Cursor~/.cursor/mcp.json or .cursor/mcp.json.cursor/skills/memoose*

User scope is the default and is usually what you want: memory follows you into every project, with a separate dataset per project directory. Use --project . when a repository should carry its own Memoose configuration for everyone who checks it out.

As a Claude Code plugin

Claude Code can load the checkout directly, which brings the MCP server, the skills, the hooks, and the memory-keeper subagent in one step:

claude --plugin-dir /path/to/memoose

Optional extras

fastembed
Real local embeddings for the vector channel of hybrid retrieval. Without it, Memoose uses a keyless hashed fallback — still no model download, still no key. Enable with uv sync --extra fastembed.
ontology
rdflib, for full OWL/RDF/Turtle parsing in import_ontology. A Turtle/RDF-XML fallback parser is built in, so this is only needed for exotic ontology files.

Verify it works

In the host, ask the agent to call two tools:

list_datasets        # is the server reachable, and which dataset is this project?
describe_ontology    # entity types, functional relations, store stats

If list_datasets answers, the core is live and every capability is available. If it does not, the MCP server is not connected: re-run the install for that host and restart it. For the automatic parts, run the memoose-onboard skill — it checks each one against the host you are actually on and reports what it found.

Develop

uv sync --extra fastembed --group dev
uv run pytest                                          # includes the maintained-memory suite
uv run python benchmarks/maintained/run_maintained.py  # ~1 s, no key
claude plugin validate .

Memoose is Apache-2.0. No API key, no service, one SQLite file per project.
